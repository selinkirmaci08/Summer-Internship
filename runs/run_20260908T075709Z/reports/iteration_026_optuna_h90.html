Overview
Configuration

Model Family & Deployment Scenario

✓ LightGBMRegressor

Deployment: Live Forecast

One model per horizon. At inference, the origin date D is known; the model predicts bread quantity for D+h using only features causal from D — no future data leakage. Weather features included only for h≤7 (7-day forecast availability constraint).

Each of the six LightGBM models is trained independently on fold-3 training rows (2010-11-16 to 2020-06-30, n=2,713) using a rolling-origin CV design. Validation is fold 3 (Sep–Dec 2020, n=95 rows post-regime). Features are constructed causally from origin date D: lag windows look back from D, seasonal anchors use only same-DOW observations prior to D. The ratio target transform (predict ratio = target / anchor, then multiply back) uses the same causal anchor at inference. h=90's 5 scoreable fold-3 validation rows required pooling all three folds for model selection.

Serving Instructions

  • Compute anchor_correct_h{h} for each horizon at inference time: seasonal median of last W same-DOW-as-TARGET observations from origin D. NAIVE_WINDOWS = {1:4, 7:4, 14:4, 30:26, 60:26, 90:13}.
  • For ratio-transform horizons (h=1,7,30,60): predicted_ratio = model.predict(features); prediction = predicted_ratio × anchor_correct_h{h}. Clip ratio to (0.05, 5.0) before multiplying.
  • For direct horizons (h=14, h=90): prediction = model.predict(features) directly in bread_quantity units.
  • Only call the model for days the store is expected to be open. Do not call for known closure days (public holidays, weekend-only operations).
  • Weather features are only valid for h≤7; set wx_* to NaN or imputed month-median for h>7 predictions.

Limitations
Known Constraints

Model Limitations & Caveats

  • h=90 fold-3 sample size (5 rows): The fold-3 validation window ends at 2020-12-31; only 5 origins satisfy D+90 ≤ 2020-12-31. All h=90 model selection uses pooled 3-fold MAE (n=140). Val MAE for h=90 carries substantially higher uncertainty than shorter horizons.
  • Ratio transform behaviour near zero: When anchor_correct_h{h} is near zero (e.g., origin window contains closure days), the ratio feature becomes numerically unstable. RATIO_CLIP (0.05, 5.0) mitigates but does not eliminate this at inference on atypical store patterns.
  • Validation representativeness: Fold 3 validation (Sep–Dec 2020, 95 rows) is fully post-regime but overlaps with COVID-related behavioural changes. The model has not been evaluated on a "clean" post-regime period (2021+). All metrics are optimistic by an unknown margin.
  • h=60 (14 estimators): The very low n_estimators for h=60 reflects early stopping on a 35-row validation window. This model is likely underfit; the test MAE of 46.3 (vs val 36.2) is consistent with high variance.
  • Stress test (2022–2023): The model was not trained on the bakery's weekend-dominant operating pattern (38% closure rate in 2022–2023). On open days only, h=14–90 performance is comparable to primary test; h=1,7 degrade due to lag contamination from surrounding closure days.
  • No retraining pipeline: These models are point-in-time. Demand trend (-28.7% over 2010–2020) continues; models should be retrained periodically with fresh data.

Durable Rules for Inference

  • All LightGBM models must use objective='regression_l1' if retrained.
  • h=60 eval: 95 val target dates (Sep–Dec 2020), features from origin D−60.
  • h=90 eval: pooled multi-fold (fold-3 alone has only 5 rows).
  • Per-horizon targets must be created by DATE JOIN (row.date + h calendar days), never by positional shift.
