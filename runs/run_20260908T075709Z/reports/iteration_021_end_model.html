h=90 CV MAE varies significantly across folds: fold 1 (30.1) vs fold 2 (82.2). This is expected — fold 1 predicts 2018Q4 from a long historical context (mean demand ~330), while fold 2 predicts 2019Q4 (lower mean ~270, steeper trend). The pooled MAE of 56.8 averages across these two demand regimes and gives a more robust estimate of generalisation error. The baseline_floor in the JSON (42.1) is the EDA provisional naive — the CV floor used for model selection (75.9 pooled) is the rolling-origin same-DOW baseline computed on the same fold windows, which is the correct comparison.

h=60 — Why Naive Wins at Iter 021

CV MAE: 71.9 vs floor: 40.0
LightGBM overfit and failed to beat the seasonal median naive on 35 validation rows.
  • Only 35 scoreable validation rows for h=60 in fold 3 — high variance in MAE estimate
  • FE4 feature set at iter 021 did not include the ratio_correct transform for h=60 (added in iter 022)
  • h=60 spans ~2 months ahead — the seasonal median baseline (w=26, 6-month same-DOW lookback) is a strong prior at this range
  • Subsequent iter 022 fix: adopted ratio_correct_h60 transform and anchor_correct_h60 anchor → model beats floor with CV MAE 36.2
Resolution: lgbm_h60_final.pkl in artifacts/training/final/ was produced by iter 022 and IS the production model for h=60.

Serving Instructions — Per-Horizon Prediction Calls

Ratio-Decoded Horizons (h=1, 7, 30, 60)

Model predicts a ratio relative to a seasonal anchor. Multiply back to get units.

# h=1 ratio = model_h1.predict(X) ratio = np.clip(ratio, 0.05, 5.0) units = ratio * anchor_correct_h1 # h=7 ratio = model_h7.predict(X) ratio = np.clip(ratio, 0.05, 5.0) units = ratio * naive_h7_seasonal_median_w4 # h=30 ratio = model_h30.predict(X) ratio = np.clip(ratio, 0.05, 5.0) units = ratio * anchor_correct_h30 # h=60 ratio = model_h60.predict(X) # iter022 model ratio = np.clip(ratio, 0.05, 5.0) units = ratio * anchor_correct_h60

Raw-Unit Horizons (h=14, 90)

Model predicts bread units directly. No ratio decode needed.

# h=14 units = model_h14.predict(X) # h=90 units = model_h90.predict(X)

Anchor Computation

Anchors are seasonal medians of past same-DOW observations. Window W per horizon:

h=1  W=4 weeks
h=7  W=4 weeks
h=30  W=26 weeks
h=60  W=26 weeks
DOW rule: anchor uses DOW of the target date (origin date + h), not the origin date's DOW. This is critical for correctness at h=1,30,60.

Durable Rules — Must Be Preserved in All Retraining

  • All LightGBM models must use objective='regression_l1' (MAE loss) — not MSE, not regression
  • h=60: use naive_h60_seasonal_median_w26 if ML MAE exceeds the CV floor — do not force an ML model that underperforms
  • h=90: use all 3 CV folds for evaluation — fold 3 alone has only 5 rows and is statistically unreliable
  • Feature set: use iter 019 FE CSV (90 cols) with fillna(0); never use raw preprocess CSV directly
  • COVID lockdown rows (is_covid_lockdown_period==1) must be excluded from training but retained in the dataset for gap/boundary purposes
  • Ratio clip: always clip predicted ratio to (0.05, 5.0) before multiplying by anchor — prevents implausible negative or runaway forecasts
